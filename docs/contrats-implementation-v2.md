# Contrats d'implémentation V2

Contrat commun Worker / interface / runner. Les champs historiques demeurent lisibles ; les générations nouvelles utilisent `schema_version: 2`.

## Données et routes privées

- Personne : `{id, display_name, role, custom_role, relationship_text, period_start, period_end, revision, created_at, updated_at}`. Rôles `father,mother,parent,partner,child,sibling,friend,best_friend,other` ; périodes texte libre (80 caractères). POST `/api/people` avec ces champs éditables et `creation_id` (UUID client obligatoire). PATCH `/api/people/:id` avec `revision` et champs modifiés. DELETE avec JSON `{revision}`. GET : `{people, next_cursor, source_version}` (50 maximum, cursor ID). Écriture : `{ok:true, person, source_version}` ; suppression `person:null`.
- Événement : `{id,title,kind,description,meaning_now,date_precision,date_start,date_end,age_text,current_importance,fiction_use,people_ids,revision,created_at,updated_at}`. Kinds `difficult,positive,turning_point,ambivalent,other`; précision `unknown,year,month,day,range,age`; dates ISO partielles suivant la précision ; `age_text` libre ; importance `null` ou 1–5 ; fiction `abstract` (défaut) ou `understanding_only`. Même CRUD `/api/life-events`, `creation_id` obligatoire, réponses `{events,next_cursor,source_version}` / `{ok:true,event,source_version}`. Liens de proches vérifiés dans le compte. Révisions en conflit : 409 `revision_conflict`. Identique : pas de changement de version. Même création rejouée : même ID ; payload différent : 409 `idempotency_conflict`.
- GET `/api/characters` : `{characters, slots:[1,2,3], status, quota, active_request, source_version, generation_paused}`. Personnage `{id,slot,identity,facet,narrative_state,canon_version,last_story_id,created_at,updated_at}` ; `identity:{name,description,...}` stable ; `facet:{label,description,evidence:[...typed IDs]}` révisable. Statut `unprepared,waiting_portrait,queued,preparing,ready`.
- POST `/api/characters/prepare` `{}` : prépare les slots manquants sans crédit, idempotent. Aucun récit automatique.
- POST `/api/characters/:id/continue` : `{idempotency_key,expected_parent_id:null|string}` ; aussi accepté en header `Idempotency-Key`. Réponse 202 `{request,quota}`. Clés stables `quota_exhausted,request_in_progress,parent_changed,context_changed,generation_paused,subscription_required`. Même clé et mêmes paramètres retourne la même demande.
- Demande publique `{id,character_id,expected_parent_id,status,credit_status,week_start,source_version,canon_version,attempts,story_id,error_code,created_at,expires_at}` ; états `waiting_portrait,queued,running,completed,failed,cancelled,expired` ; crédits `reserved,consumed,released`. GET `/api/story-requests/:id` et POST `/api/story-requests/:id/cancel` retournent `{request,quota}`. Quota `{limit:7,used,reserved,remaining,week_start,renews_at,time_zone:'Europe/Paris'}`.
- GET `/api/stories?character_id=…&cursor=…` : `{stories,next_cursor}` ; histoire comprend anciens champs + `character_id,request_id,episode_number,parent_story_id,source_version,canon_version,narrative_delta`. Détail inchangé `{story,feedback}`. Canonique `/mes-personnages/?personnage=ID&story=ID` ; anciennes routes redirigent en conservant paramètres.
- Feedback PUT existant : champs historiques + `differences` (4000), `scope` (`overall,situation,reaction,character,style`), `preference` (4000), `avoid` (4000), `revision` optionnelle transition. La correction est autobiographique, préférence/avoid sont des souhaits de lecture.
- Erreurs JSON `{error:<texte>,code:<code stable>}` ; authentification, Origin, no-store inchangés.

## Sources canoniques et portrait

`context.sources` et `job.sources` sont des tableaux `{id,type,revision,hash,created_at,updated_at,text,explicit,temporal,fiction_use,fields}`. IDs : `like:<article_id>`, `feedback:<story_id>`, `memory:<user_id>`, `person:<id>`, `event:<id>`. `fields` contient les textes séparés (reason/differences/correction/preference/avoid etc.). Le texte canonique concatène les champs avec libellés ; les citations doivent être des sous-chaînes exactes de `source.text`. Les likes sans commentaire restent intérêt de lecture uniquement ; rôles/alias seuls ne sont pas source de personnalisation. `source_manifest` : `{[id]:{revision,hash,type,explicit}}` construit serveur. `people` / `events` complets sont aussi disponibles dans le contexte de recommandation.

Portrait V2 : `{schema_version:2, summary,summary_evidence:[IDs], axes:[{label,why,confidence,evidence:[IDs],claim_type:'interest'|'hypothesis'|'declaration'}], strengths:[{text,evidence:[IDs]}], uncertainties:[strings], current_state?:{summary,evidence:[IDs]}, evolution?:{summary,evidence:[IDs]}, reading_preferences?:{preferred:[{label,evidence:[IDs]}],avoid:[...]}, citations:[{source_id,revision,quote}], coverage?:{processed:[IDs],pending:[IDs]}}`. Chaque ID cité dans le portrait doit avoir au moins une citation valide avec révision actuelle, extrait non vide exact et source autorisée. Aucune prose non sourcée pour résumé/forces/états. Les axes fondés uniquement sur like nu sont `interest`, confiance ≤0,25. Aucune `fictional_character` dans le nouveau portrait. Les portraits V1 sont invalidés, exclus du classement et des briefs ; identité fictive seulement migrée au slot 1.

## Jobs internes (OIDC inchangé)

Claim renvoie au plus un job `{id,kind,user_id,lease_token,source_version,profile_version,memory_version,day,memory,likes,feedback,people,events,sources,source_manifest,portrait_previous:null,portrait_previous_version:0}`. Les jobs utilisent `schema_version:2`.

- `portrait` : completion `{lease_token,source_version,memory_version,portrait:<V2>}`.
- `characters` : claim ajoute `portrait`, `characters` existants, `missing_slots`. Completion `{...,characters:[{slot,identity:{name,description,...},facet:{label,description,evidence:[IDs]},narrative_state:{...}}]}` ; seulement slots manquants, aucun changement d'identité existante.
- `story` : claim ajoute `request_id,character_id,character,expected_parent_id,canon_version,portrait,inspirations,history` (du seul personnage, tous les résumés disponibles), `request` (compteurs cumulés). Completion anciens `title,body,summary,reflection_questions,practice` + `narrative_delta` objet ; `summary` résume le récit final complet ; `narrative_delta` contient citations de passages du récit final. Replay completion retourne le même story_id. Source changée : rebase même demande/semaine/crédit/budget, jamais nouvelle demande.
- `/llm` accepte `temperature` 0–1 (défaut selon purpose), réserve appels/tokens avant envoi ; max 20 appels cumulés / demande et 3 tentatives. `/fail` garde la demande et son coût ou libère au troisième échec.

Kill switch `GENERATION_PAUSED=true` bloque claims, nouvelles préparations/continuations, appels et completions ; conserve lecture/CRUD/exports. L'ancien ordonnanceur quotidien est supprimé.


## Précisions finales validées

- Les facettes stockent un `source_manifest` ajouté côté serveur. Un lien retiré, une révision ou une empreinte modifiée neutralise la prose périmée à la lecture, à l'export et dans les jobs. L'identité et le canon fictifs restent stables. Si toutes les sources sont `understanding_only`, une facette `exploratory:true` avec `evidence:[]` est permise ; elle n'affirme aucune interprétation personnelle.
- `coverage.pending` non vide maintient le portrait provisoire, interdit personnages/histoires, puis ouvre une nouvelle tranche de portrait au même `source_version`. Les dérivés déjà validés sont réutilisés ; le budget gratuit de trois démarrages / 24 h et dix minutes d'intervalle reste applicable.
- Le job contient `source_derivatives:[{source_id,revision,source_hash,analysis_version:2,derivative:{signals:[{kind,text,quote,temporal}]},manifest}]`. La completion portrait peut fournir les nouvelles extractions dans le même champ ; le serveur valide les citations et reconstruit le manifeste. Aucune extraction périmée n'est réutilisée.
- Les jobs exposent les compteurs cumulés `provider_calls,attempts,reserved_tokens`. Le proxy renvoie `content` et `usage:{input_tokens,output_tokens,observed_cost}`. Réservation technique avant appel, non remboursée sur réponse réseau incertaine ; plafonds configurables `STORY_TOKEN_BUDGET` (300000 par défaut) et `WEEKLY_TOKEN_BUDGET` (3000000 par défaut). Le plafond de 20 appels reste par demande d'histoire, toutes tentatives et réanalyses confondues. Trente nouvelles demandes au maximum / 24 h préviennent les cycles d'échecs répétés.
- `character_histories` des jobs de préparation associe chaque ID existant aux résumés de ses archives ; le corps du premier et du dernier épisode est inclus lorsqu'une ancienne identité doit être reconstruite. Le job d'histoire contient uniquement l'historique du personnage choisi.
- Les expositions de recommandations conservent uniquement les derniers 100 IDs publics et leurs dates sur sept jours. Elles ne modifient jamais `source_version` ni les preuves personnelles ; export et suppression les incluent. Migration additionnelle : `0006_recommendation_exposures.sql`.
- La projection privée lit des lignes bornées et vérifie la version avant/après, avec reprise sans appel IA en cas de modification simultanée. Elle reste complète à la limite de 500 événements sans construire une cellule SQL JSON géante.
